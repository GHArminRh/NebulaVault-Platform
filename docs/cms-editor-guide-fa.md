# راهنمای کامل مدیریت محتوای نبیولا والت با django CMS

این راهنما برای ویرایش صفحهٔ اصلی منتشرشده در نشانی `/` و ساخت صفحه‌های محتوایی مستقل، بدون تغییر کد یا دست‌کاری قالب اصلی سایت است.

## شروع کار

1. با حساب کارکنانی که مجوز ویرایش CMS دارد وارد سایت شوید.
2. نشانی اصلی سایت (`/`) را باز کنید و از نوار django CMS حالت **Edit** را فعال کنید. صفحهٔ خانهٔ منتشرشده در CMS همان صفحه‌ای است که در این نشانی نمایش داده می‌شود.
3. برای ویرایش هر بخش، روی همان بخش کلیک یا دوبار کلیک کنید؛ برای افزودن بلوک، از **Add plugin / Create** در محل موردنظر استفاده کنید.
4. تغییرات را ذخیره و صفحه را منتشر کنید؛ سپس از **Preview** و یک پنجرهٔ ناشناس برای بررسی خروجی عمومی استفاده کنید.

صفحهٔ اصلی موجود به‌صورت خودکار از قالب «صفحهٔ اصلی قابل ویرایش نبیولا والت» استفاده می‌کند. نیازی به ساخت صفحهٔ اصلی دوم نیست. اگر یک استقرار قدیمی placeholder خالی داشته باشد، bootstrap پس از اجرای migration فقط بخش‌های گمشده را اضافه می‌کند و متن‌های ویرایش‌شده و بلوک‌های موجود را حذف نمی‌کند.

## بخش‌های صفحهٔ اصلی

- **Hero / معرفی:** متن اصلی، دکمه‌ها و بخش بصری آغاز صفحه؛ قابل ویرایش به‌عنوان بلوک متن.
- **محصولات زنده:** از محصولات فعال کاتالوگ می‌خواند؛ اطلاعات محصول را در CMS دوباره وارد نکنید.
- **تعرفه‌های زنده:** نام طرح، قیمت، واحد پول و مدت را از طرح‌های فعال می‌خواند.
- **امکانات:** متن و کارت‌های معرفی امکانات، قابل ویرایش از CMS.
- **مقالات تازه:** در placeholder مستقل «مقالات تازه» با افزونهٔ زندهٔ `LiveBlogListPlugin`، مقاله‌های منتشرشده را از بلاگ نمایش می‌دهد.
- **نسخه‌های منتشرشده:** نسخه‌های عمومی و لینک‌های دریافت را از کاتالوگ نسخه‌ها می‌خواند.
- **پرسش‌های رایج و دعوت به اقدام:** متن و پیوندهای انتهای صفحه، قابل ویرایش از CMS.

بلوک‌های زنده با تغییر اطلاعات اصلی در پنل مدیریت به‌روزرسانی می‌شوند؛ CMS محل چیدمان و ارائهٔ محتواست، نه جایگزین کاتالوگ محصولات، سفارش‌ها یا اطلاعات لایسنس.

## ابزارهای قابل استفاده در ویرایشگر

در placeholder عمومی «محتوای تکمیلی» و بخش‌های متنی «امکانات» و «معرفی»، ابزارهای زیر در دسترس‌اند. مجموعهٔ frontend بر پایهٔ `djangocms-frontend 2.5.3` و خروجی Bootstrap 5 تنظیم شده است:

- **متن:** افزونهٔ Text با ویرایشگر TipTap (ویرایش درون‌صفحه‌ای، قالب‌بندی و پیوندها).
- **تصویر:** تصویر با URL خارجی؛ بارگذاری مستقیم فقط با ذخیره‌سازی پایدار S3-compatible فعال می‌شود.
- **چیدمان:** Container، Row و Column برای ساخت ساختار چندستونه و واکنش‌گرا.
- **کارت:** Card layout، Card و Card inner برای ساخت کارت‌های محتوا.
- **بلوک‌های محتوا:** Alert، Blockquote، Code و Figure.
- **محتوای زنده:** محصولات، تعرفه‌ها، نسخه‌های منتشرشده و مقالات تازه از اطلاعات اصلی خود سایت خوانده می‌شوند.

ستون‌ها باید داخل Row و اجزای داخلی کارت داخل Card قرار بگیرند؛ محدودیت والد/فرزند افزونه‌ها عمداً حفظ شده تا ساختار HTML و چیدمان صفحه خراب نشود. بخش‌های محصولات، تعرفه‌ها، نسخه‌ها و بلاگ placeholderهای اختصاصی دارند تا محتوای زنده در محل درست خود قرار گیرد.

ویرایشگر TipTap متعلق به افزونهٔ `djangocms-text` است. TinyMCE تنظیم‌شده در پروژه برای فیلدهای متنی کاتالوگ و سایر فرم‌های جداگانه است و به‌طور خودکار ویرایشگر Text در CMS را تغییر نمی‌دهد.

## ساخت صفحهٔ عمومی جدید

1. از مدیریت صفحه‌ها یک صفحهٔ جدید بسازید و عنوان و نشانی یکتا تعیین کنید.
2. قالب «صفحهٔ عمومی نبیولا والت» را انتخاب کنید.
3. در حالت ویرایش، از بلوک‌های متن، چیدمان، کارت، محتوا، اعلان و افزونه‌های اختصاصی نبیولا استفاده کنید.
4. پیش‌نمایش را بررسی کنید و سپس صفحه را منتشر کنید. مسیر صفحه‌های عادی زیر /pages/ است.

## تصویرها و فایل‌های رسانه‌ای

- افزونهٔ «تصویر با آدرس اینترنتی» برای URL پایدار HTTP/HTTPS در دسترس است؛ متن جایگزین توصیفی وارد کنید.
- بارگذاری مستقیم تصویر فقط پس از پیکربندی ذخیره‌سازی پایدار S3-compatible فعال می‌شود. فایل‌سیستم محلی Render Free موقت است و برای نگهداری رسانه مناسب نیست.
- برای فعال‌کردن بارگذاری مستقیم، این متغیرها باید در تنظیمات محیطی Render پیکربندی شوند:
  - CMS_MEDIA_STORAGE_BACKEND=s3
  - AWS_STORAGE_BUCKET_NAME
  - AWS_ACCESS_KEY_ID
  - AWS_SECRET_ACCESS_KEY
  - AWS_S3_REGION_NAME (در صورت نیاز)
  - AWS_S3_ENDPOINT_URL (برای ارائه‌دهندهٔ S3-compatible غیر از AWS)
  - AWS_S3_CUSTOM_DOMAIN (اختیاری، برای CDN یا دامنهٔ رسانه)
  - AWS_QUERYSTRING_AUTH=False فقط برای رسانه‌هایی که باید عمومی باشند.

هیچ باکت یا اعتبارنامه‌ای به‌صورت خودکار ساخته نمی‌شود. تا وقتی فضای ذخیره‌سازی پایدار پیکربندی نشده، گزینهٔ بارگذاری مستقیم عمداً نمایش داده نمی‌شود.

## چک‌لیست قبل از انتشار

- تیترها، پیوندها و متن جایگزین تصویرها را بررسی کنید.
- پیوندهای «محصولات»، «تعرفه‌ها»، «امکانات»، «نسخه‌ها» و «پرسش‌ها» را آزمایش کنید.
- پیش‌نمایش دسکتاپ و موبایل را بررسی کنید؛ از عرض ثابت یا استایل inline برای تعیین اندازهٔ کلی صفحه استفاده نکنید.
- مطمئن شوید بخش‌های زنده در خروجی عمومی داده دارند و در حالت بدون داده پیام مناسب نشان می‌دهند.
- بعد از انتشار، صفحهٔ اصلی را با بارگذاری مجدد کامل بررسی کنید.

## محدودهٔ تغییرات و سازگاری

- ظاهر و صفحهٔ ورود Django Admin انگلیسی و بدون تغییر باقی می‌ماند.
- حساب مشتری، تأیید ایمیل، پرداخت زرین‌پال، سبد خرید، API و لایسنس دسکتاپ از CMS مستقل‌اند.
- مسیر `/` ابتدا صفحهٔ خانهٔ منتشرشدهٔ CMS را نمایش می‌دهد. اگر چنین صفحه‌ای وجود نداشته باشد یا CMS برای آن پاسخ 404 بدهد، سایت به قالب فروشگاه قبلی برمی‌گردد تا سایت عمومی از دسترس خارج نشود.
