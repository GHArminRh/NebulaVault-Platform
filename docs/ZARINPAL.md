# راه‌اندازی درگاه زرین‌پال

این پیاده‌سازی از بسته رسمی Python SDK زرین‌پال استفاده می‌کند و گردش درخواست پرداخت، انتقال به صفحه پرداخت، callback و تأیید سمت سرور را متصل می‌کند. تا وقتی تأیید سمت سرور موفق نشده باشد، سفارش پرداخت‌شده ثبت نمی‌شود و اشتراک/لایسنس فعال یا تمدید نمی‌شود.

## ۱. آماده‌سازی حساب

1. در پنل زرین‌پال، پذیرنده و دسترسی API را آماده کنید.
2. Merchant ID را از پنل دریافت کنید. اگر حساب شما برای SDK به Access Token نیاز دارد، آن را نیز از پنل دریافت کنید.
3. یک دامنه عمومی با HTTPS به سرور وصل کنید؛ endpoint بازگشت باید از اینترنت قابل دسترس باشد.
4. ابتدا از محیط sandbox برای آزمون استفاده کنید. پس از تکمیل تست‌ها و آماده‌شدن پذیرنده، sandbox را خاموش کنید.

## ۲. متغیرهای محیطی

مقادیر را در محیط استقرار یا فایل خصوصی .env سرور قرار دهید؛ مقادیر واقعی را در Git ثبت نکنید:

    ZARINPAL_MERCHANT_ID=your-merchant-id
    ZARINPAL_ACCESS_TOKEN=
    ZARINPAL_SANDBOX=True
    ZARINPAL_PUBLIC_BASE_URL=https://your-public-domain.example
    ZARINPAL_HTTP_TIMEOUT=15
    NEBULA_MOCK_PAYMENTS=False

- ZARINPAL_PUBLIC_BASE_URL فقط origin سایت است؛ مسیر callback توسط برنامه ساخته می‌شود.
- در محیط عملیاتی از HTTPS استفاده کنید و ZARINPAL_SANDBOX=False قرار دهید.
- NEBULA_MOCK_PAYMENTS=False باعث می‌شود checkout به‌جای نهایی‌کردن ساختگی، سفارش‌های درگاه را ایجاد کند.
- کلیدها و token زرین‌پال را داخل کد، قالب‌ها یا فایل‌های عمومی قرار ندهید.

## ۳. واحد پول و مبلغ

مدل طرح‌ها مبلغ را در price_minor_units و واحد را در currency نگه می‌دارد. برای این اتصال، هر طرحی که از زرین‌پال استفاده می‌کند باید currency=IRR داشته باشد و مبلغ ذخیره‌شده در واحد ریال باشد، نه تومان. مبلغ باید حداقل ۱۰۰۰ ریال باشد. سیستم عمداً قیمت را خودکار از تومان به ریال تبدیل نمی‌کند؛ واحد را در پنل مدیریت به‌درستی ثبت کنید.

## ۴. گردش پرداخت

- سفارش با قیمت سمت سرور ثبت می‌شود.
- تلاش پرداخت برای همان سفارش یک شناسه یکتا دارد و authority دریافتی از زرین‌پال در دیتابیس ذخیره می‌شود.
- کاربر به صفحه پرداخت زرین‌پال هدایت می‌شود.
- در callback، پارامتر Status مرورگر به‌تنهایی کافی نیست؛ سرور با authority و مبلغ ذخیره‌شده خودش از API تأیید زرین‌پال استعلام می‌کند.
- پس از تأیید، تابع نهایی‌سازی موجود سفارش را پرداخت‌شده می‌کند و اشتراک/لایسنس را ایجاد یا تمدید می‌کند.
- callback تکراری پس از تأیید برای ایجاد اشتراک یا تمدید دوباره بی‌خطر است.
- برای سبدی با چند طرح، هر طرح یک سفارش جداگانه است؛ در صفحه سفارش‌ها هر سفارش را جدا پرداخت کنید.

## ۵. اعمال migration و تست

بعد از دریافت شاخه، محیط مجازی را فعال کنید و این دستورات را اجرا کنید:

    python -m pip install -r requirements.txt
    python manage.py migrate
    python manage.py check
    python manage.py test billing

قبل از فعال‌سازی روی سایت اصلی، با sandbox خرید اولیه و تمدید را امتحان کنید. callback لغوشده، callback تکراری، timeout ارتباط، خطای تأیید و بازگشت به صفحه سفارش‌ها را نیز بررسی کنید. برای محیط عملیاتی، تنظیمات HTTPS و proxy، ایمیل صدور لایسنس و دسترسی عمومی callback باید درست باشند.
