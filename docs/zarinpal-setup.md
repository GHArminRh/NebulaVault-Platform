# راه‌اندازی درگاه زرین‌پال

## تنظیم متغیرهای محیطی

در فایل محیطی سرور (نه داخل Git) این مقادیر را تنظیم کنید:

- `ZARINPAL_MERCHANT_ID`: شناسه پذیرنده از پنل زرین‌پال.
- `ZARINPAL_SANDBOX=true`: فقط برای آزمایش؛ برای پرداخت واقعی پس از دریافت تأیید پذیرنده، `false` کنید.
- `ZARINPAL_CALLBACK_BASE_URL`: دامنه عمومی HTTPS سایت، برای نمونه `https://example.com` (در صورت نیاز به دامنه ثابت پشت reverse proxy).

مسیر بازگشت: `/billing/zarinpal/callback/?attempt=<UUID>`. این مسیر باید از اینترنت و با HTTPS در دسترس باشد.

## واحد پول

زرین‌پال API مبلغ را به **ریال** می‌گیرد. این اتصال عمداً فقط سفارش‌هایی با `currency=IRR` را قبول می‌کند و مقدار `amount_minor_units` را ریال فرض می‌کند. طرح‌هایی با تومان یا USD را قبل از فروش تبدیل/تعریف دقیق کنید؛ تبدیل حدسی انجام نمی‌شود. حداقل مبلغ این adapter برابر ۱۰۰۰ ریال است.

## نصب و استقرار

```powershell
pip install -r requirements.txt
python manage.py check
python manage.py test billing.tests_zarinpal
```

پس از تنظیم env و استقرار، ابتدا با sandbox تست کنید. برای فعال‌کردن حالت واقعی، Merchant ID واقعی را تنظیم و `ZARINPAL_SANDBOX=false` کنید. پرداخت واقعی در این محیط آزمایش نشده است.

## جریان امن پرداخت

1. کاربر وارد حساب می‌شود و برای سفارش خودش درخواست پرداخت می‌فرستد.
2. مبلغ از سفارش ذخیره‌شده سرور خوانده می‌شود؛ مبلغی از مرورگر پذیرفته نمی‌شود.
3. سرور درخواست درگاه را ایجاد می‌کند و کاربر را به StartPay می‌فرستد.
4. callback فقط با `Status=OK` ادامه می‌یابد و سرور به API verify زرین‌پال درخواست می‌زند.
5. تنها پس از پاسخ تأیید، `finalize_payment` اجرا می‌شود؛ بنابراین callback به‌تنهایی سفارش را paid نمی‌کند.

اگر درگاه Authority را برگرداند، آن مقدار موقتاً در `PaymentAttempt.provider_reference` نگهداری می‌شود تا به تلاش پرداخت مشخص متصل بماند؛ پس از verify، سرویس نهایی‌سازی آن را با RefID واقعی جایگزین می‌کند.
