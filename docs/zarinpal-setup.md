# راه‌اندازی درگاه زرین‌پال در Nebula Vault

این پروژه از API نسخه ۴ زرین‌پال برای ایجاد درخواست پرداخت و تأیید سمت سرور استفاده می‌کند.

## تنظیمات محیط

مقادیر زیر را در فایل `.env` واقعی سرور قرار دهید؛ تغییر `.env.example` به‌تنهایی تنظیمات سرور در حال اجرا را عوض نمی‌کند:

```dotenv
ZARINPAL_MERCHANT_ID=your-merchant-id
ZARINPAL_SANDBOX=True
ZARINPAL_ENABLED=True
DJANGO_DEBUG=True
```

تنظیم پیش‌فرض این پروژه برای تست، `ZARINPAL_SANDBOX=True` است؛ حتماً `ZARINPAL_MERCHANT_ID` را با شناسه پذیرنده آزمایشی (sandbox) جایگزین کنید. برای پرداخت واقعی، فقط پس از آمادگی عملیاتی `ZARINPAL_SANDBOX=False` و شناسه پذیرنده زنده را تنظیم کنید؛ شناسه زنده و آزمایشی را با هم جابه‌جا نکنید.

مسیر پرداخت ساختگی داخلی از برنامه حذف شده است. برای آزمایش از حالت Sandbox خود زرین‌پال با شناسه پذیرنده آزمایشی استفاده کنید. در محیط عملیاتی حتماً `DJANGO_DEBUG=False` باشد.

## آدرس بازگشت

هنگام ایجاد درخواست، آدرس callback از دامنه‌ای که کاربر باز کرده ساخته می‌شود. در محیط عملیاتی، سایت باید از اینترنت و ترجیحاً با HTTPS در دسترس باشد و دامنه و تنظیمات پذیرنده در پنل زرین‌پال با آن مطابقت داشته باشند.

مسیر callback:

`https://YOUR_DOMAIN/billing/zarinpal/callback/`

در reverse proxy، مطمئن شوید Django طرح HTTPS درخواست را به‌درستی تشخیص می‌دهد؛ در غیر این صورت ممکن است callback با `http://` ساخته شود.

## روند پرداخت

1. کاربر وارد حساب می‌شود و یک طرح با واحد پول `IRR` (ریال) یا `IRT` (تومان) به سبد خرید اضافه می‌کند.

طرح‌های جدید اکنون به‌صورت پیش‌فرض با واحد `IRR` ساخته می‌شوند. طرح‌های موجود در پایگاه داده به‌صورت خودکار تغییر نمی‌کنند؛ در پنل مدیریت، از بخش Catalog → Subscription plans واحد پول طرح‌های قبلی را به `IRR` تغییر دهید و قیمت ریالی صحیح را هم وارد کنید.
2. دکمه «پرداخت این طرح با زرین‌پال» یک سفارش و تلاش پرداخت در سرور ثبت می‌کند.
3. کاربر به صفحه پرداخت زرین‌پال منتقل می‌شود.
4. پس از بازگشت، سرور کد `Authority` را با مبلغ ذخیره‌شده همان تلاش پرداخت به API تأیید می‌فرستد.
5. تنها در صورت پاسخ تأییدشده، سرویس نهایی‌سازی پرداخت اجرا و دسترسی/لایسنس سفارش فعال می‌شود.

هر طرح در سبد فعلاً یک سفارش جداگانه است؛ پرداخت یک‌جای چند طرح با یک تراکنش در مدل فعلی سفارش پیاده‌سازی نشده است.

## تست‌ها

از ریشه پروژه در محیط مجازی اجرا کنید:

```powershell
python manage.py test billing.test_zarinpal
```

این تست‌ها درخواست‌های HTTP را mock می‌کنند؛ برای تأیید واقعی حساب، دامنه، دسترسی شبکه و callback باید یک پرداخت آزمایشی/واقعی مطابق تنظیمات پذیرنده انجام شود.
